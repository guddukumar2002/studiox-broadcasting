## Authentication Flow

1. User submits email + password on /auth/login (validated with Zod schema via React Hook Form).
2. authService.login() simulates POST /api/auth/login with a 800ms delay.
3. On success: token + user object are stored via authService.saveSession() (localStorage).
4. AuthContext reads the saved session on mount so the session persists across refreshes.
5. Role-based redirect: teacher → /teacher/dashboard, principal → /principal/dashboard.
6. On logout: authService.clearSession() wipes localStorage and redirects to /auth/login.
7. DashboardLayout guards all protected routes — unauthenticated users are redirected to login.

## Role-Based Routing

- Root page.js reads user.role and redirects accordingly.
- DashboardLayout renders different nav links per role (teacherLinks vs principalLinks).
- DashboardLayout enforces role guard: teachers visiting /principal/* are redirected to /teacher/dashboard and vice versa.
- /live/:teacherId is fully public — no auth required.

## API Integration Approach

All data operations go through the service layer — NEVER directly inside components:

  components → hooks → services → utils/mockData (localStorage)

- services/auth.service.js      → handles auth token lifecycle
- services/content.service.js   → handles content CRUD + getByStatus
- services/approval.service.js  → handles approve/reject operations

Each service method simulates a real async API call with setTimeout delays.
To connect a real backend, only the service files need to change — hooks and components stay the same.

useCreateContent hook wraps contentService.create() so the upload page never calls the service directly.

Token attachment pattern (documented in all service files, ready to activate):
  axios.interceptors.request.use((config) => {
    const token = authService.getToken();
    if (token) config.headers.Authorization = `Bearer ${token}`;
    return config;
  });

## State Management Approach

- AuthContext (React Context): global user session state.
- Custom hooks (useContent, useApprovals): encapsulate loading/error/data per feature.
- Local component state: UI-only state (filters, search, modal open/close).
- No prop drilling: hooks are consumed directly in page components.
- useMemo: used in dashboard and list pages to avoid recomputing filtered/stats data on every render.

## Form Handling

- React Hook Form + Zod used on login and upload pages.
- Login schema: email (required + valid format), password (required).
- Upload schema: all fields required, end time > start time (cross-field refinement), rotation min 10s.
- File validation (outside RHF): type restricted to JPG/PNG/GIF, max 10MB.
- Inline field-level error messages shown below each input.
- Server/API errors shown as a banner above the form (not alert()).

## Scheduling Status Indicators

ScheduleBadge component computes status from startTime/endTime at render time:
  - Scheduled: now < startTime
  - Active:     startTime <= now <= endTime  (with animated pulse dot)
  - Expired:    now > endTime

Shown on: My Content cards, All Content table, Teacher dashboard recent activity.

## Performance Considerations

- useMemo for filtered lists and stats calculations.
- lazy loading on all <img> tags (loading="lazy").
- Skeleton loaders (SkeletonCard, SkeletonRow, SkeletonStatCard) shown during data fetch.
- Polling on /live page uses setInterval inside useEffect with proper cleanup.
- Pagination on All Content page (20 items/page) — handles 500–1000 item lists without DOM overload.
- 50 seed items generated in mockData.js to simulate realistic dataset for evaluation.
- useMemo for paginated slice computation — avoids recomputing on unrelated state changes.

## Edge Cases Handled

- Empty data: EmptyState component shown when lists are empty.
- API errors: ErrorState / inline error banner shown with retry button on all pages.
- Invalid login: inline error banner (no alert()).
- Invalid file type: blocked before FileReader with clear error message.
- File too large: blocked before FileReader with clear error message.
- Unauthenticated access: DashboardLayout redirects to /auth/login.
- Wrong role access: DashboardLayout redirects teacher from /principal/* and vice versa.
- Broken API response: try/catch in all service methods and hooks; localStorage parse errors caught.
- No live content: /live page shows "No content available" empty state.
- localStorage quota exceeded: saveStore catches QuotaExceededError silently.
- Pagination edge case: safePage = Math.min(page, totalPages) prevents out-of-bounds slice.

## Assumptions

- No real backend exists; localStorage simulates persistence for demo purposes.
- Files are stored as Base64 data URLs in localStorage (limited to ~10MB per file).
- Token is a mock base64 string; real implementation would use JWT from backend.
- Polling interval on the live page is 5 seconds (configurable in useLiveContent hook).
- Only one active broadcast per teacher is shown on the live page (first match).
- The "+12% trending" stat on the original dashboard was replaced with a real approval rate %.
